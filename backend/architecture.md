# Backend architecture

The implemented slice uses one Python backend process, one SQLite database and one authoritative engine Unix socket per world. Four worlds are four independent stacks behind a router/proxy. The C++ engine owns simulation, command ordering, costs/ownership, entity generations and game saves. A separate native renderer owns genuine UI pixels and cannot execute gameplay mutations. Provider inference remains outside both.

Independent design reviews and the coordinating peer approved this boundary before revision 2 implementation. The detailed decision record is [design-review.md](design-review.md). Full MVP acceptance, load and joint fault-recovery gates remain separate from that design approval.

## Public boundary

`Service.handle(method,path,token,body,query)` authenticates an opaque credential to an immutable identity/world/company/run/mode before routing. The HTTP adapter exposes versioned JSON, resumable SSE and authenticated binary PNG. Public routes never expose console/admin/script execution, save files, native command buffers, filesystem paths or company membership grants. Operator CLI provisioning is separate.

Both perception modes use the same 103 programmable actions and native company/ownership rules through the existing action endpoint and durable ledger. Mode controls observation permissions: structured world queries remain text-only, while visual runs examine genuine PNGs. Semantic actions require neither a renderer nor an image. Both modes receive direct command feedback (success, actual cost, native failure text and returned references/tokens); visual projection excludes capacity/refit statistics and unrelated state. Optional visual `ui.apply` retains screenshot-bound input and its request ID/status-only receipt.

The engine-generated [catalog snapshot](schemas/engine-catalog-v1.json) describes the shared programmable actions, optional visual `ui.apply`, text queries and a finite `conventions.control_reference` schema. The [public envelope schema](schemas/public-api-v1.json) documents the boundary. Backend validation uses that one canonical schema per action; C++ resolves live targets, ownership and gameplay rules. World hello must match the exact catalog hash. Renderer hello is separately fenced by renderer role/world/epoch/instance; its private RPC stays read-only. Capabilities advertise shared actions even when no renderer is configured.

Station and vehicle handles carry `id`, `generation` and the observed opaque `engine_instance_id` (1–256 characters). The instance fences restored worlds where a pool slot and generation may recur. Fresh action and query inputs require all three fields; the caller's instance is never replaced by the current transport envelope's instance. Engine-supplied instances pass through positive projection unchanged. Historical two-field action receipts retain their original shape. Authentication, immutable caller binding and bounded envelope checks apply to every request. Exact canonical duplicate lookup precedes current operation, schema and renderer checks, so an old receipt remains readable and retryable without granting permission for a fresh legacy-handle command or retired operation. Catalog changes are imported at process start; upgrade new backend and native processes together without changing in-flight stacks.

`POST /v1/control/reference` is a read-only authority RPC for one explicitly selected current target. Its closed selector comes from the native catalog convention, and its positive response contains only an entity handle, an engine ID, and applicable opaque order/page mutation tokens. No structured observation is invoked. Explicit IDs select the current occupant, with no cross-boot identity or automatic refresh promise. Missing/ambiguous/unauthorized/admission-limited targets share `409 control_reference_unavailable`. Scan and token-producing lookups share the existing global one-second expensive text/refit admission budget. Native permission checks still decide which actions may use the reference. Order/page tokens accept native upper- or lowercase hex and pass through unchanged; mutation checks compare the opaque token exactly.

The small decision-information projection adds native vehicle status, fixed cargo-payment samples, current bridge designs and selected-model purchase performance to the existing text observation route. Each DTO intersects native `result_fields` with a finite backend field vocabulary. Native code owns the 20-sample/13-bridge and response-byte bounds; backend projection preserves signed income, nullable bridge speed and omitted inapplicable performance fields without recalculation or caching. Generated catalog replacement remains coupled to an actual matching native export.

Custom-news observation uses native bounded encoded retention and one metadata-only `news.custom` query. The backend projects finite cursor, date, type and kind-specific historical-reference fields; it stores no news archive and never refreshes historical targets. One disjoint `display.text` selector reads a retained item through the existing selected native rendering path. Body formatting is live, so content versions can change; list rows contain neither previews nor encoded data. New query schemas enter only through the reviewed native catalog export.

The optional `POST /v1/actions/estimate` route sends one existing typed action through the native Shift test path for either perception mode. It uses current catalog, actor and world fences, plus native recovery/checkpoint checks independent of ledger reservation. Its dedicated projector requires exact scalar types, signed int64 cost, advisory and NoTest flags, and bounded failure text; it drops references, state and other undeclared fields. No action row, sequence, event, dispatcher retry or renderer work is created. Native enforces a separate global one-second estimate gate and a 4096-byte result bound. Native Shift auxiliary storage/generation bookkeeping remains possible; this is advisory command feedback with no gameplay execution, not a general rollback facility.

Both perception modes share `GET /v1/world/status` and finite `world.status` notifications. The status handler reads the run's current durable cursor before a fresh native hello, with no database lock held across RPC. Its projector exposes only native pause truth, ordered reasons, command policy and boot-qualified revision. Recovering or unavailable status fails closed. Native event IDs and instance are checked; pause fanout and the existing broker offset commit in one transaction. First-instance and ring-gap baselines use fresh status, with another hello after a detected gap and an abort if its fence changed. Existing run event retention supplies replay; no status cache, table or journal is added.

Native publication tests the actual queued command against the native pause predicate. Disallowed queued typed API commands receive terminal uncharged `world_paused` under their original identity, while permitted categories follow native rules. Exact retry remains a receipt read; there is no retained forbidden queue, automatic resume replay, broker rotation or checkpoint exception. This deliberately differs from native human queue waiting in the publication race.

## State and request lifecycle

SQLite WAL, FULL synchronous writes and explicit transactions persist identities, memberships, immutable runs, hashed credentials, action rows, projected recipient events, messages/ACL snapshots, moderation and checkpoint observations. Reconnect uses the same run; credential rotation does not alter mode or request identity. Public provisioning cannot create a spectator or internal service credential.

Admission atomically allocates one permanent monotonic per-world `request_sequence` and inserts an `action_requests` row. Unique `(world,identity,request_id)` plus canonical payload/run/company/mode detects retries and conflicts. The action table is the engine dispatch queue; no generic workflow or second execution counter exists. Internal native chat delivery uses the same allocator/table, with no public credential.

The broker runs in one bounded world thread outside HTTP handlers. Public acknowledgment follows durable admission and does not wait for engine execution. Company work drains fairly with a bounded budget. The broker persists a queued marker before sending and polls immutable request IDs afterward; uncertain transport never causes blind replay. Native frame/tick, not backend sequence, determines execution order. Engine replies are not public DTOs.

Optional `ui.apply` gestures reuse that action row and request sequence. The original public `ui.apply` payload is immutable. Under the run's renderer lock, the broker validates the latest owned image and commits `intent_state=capturing` with `expected_worker_instance_id` before `ui.capture` may click. The private worker intercepts at most one native command (or an empty UI-only bundle). The backend validates the source worker/authority binding and persists the complete immutable `visual_intent` before sending `action.submit` with the unchanged public action and that private bundle. Only `ui.apply` dispatch and recovery require a persisted bundle; semantic actions from visual runs follow the ordinary typed path. A capture failure, lost reply or crash with the marker but no bundle is atomically aborted as `rejected/visual_capture_aborted`, because no authority dispatch could have occurred. Cleanup is fenced to the recorded worker generation; no retry reclicks or silently binds a new worker. A persisted bundle is reconciled with the same request sequence and exact payload through the authority ledger. An authority-queued action with an ambiguous outcome remains `uncertain`.

The authority validates the source frame lease, owner, targets and normal game rules and records the terminal outcome independently of replica UI replay. After persisting that terminal result, the backend calls the existing worker `ui.release(commit|reject)`; the worker's normal owner-only network callback supplies rendered gameplay feedback. `ui.status` reconciles release, and the cached bundle is acknowledged only after a durable authority terminal result and a completed/rejected worker phase. A persisted `ui_state` lets cleanup skip an already completed commit and retry acknowledgement directly; unknown acknowledgement is idempotent in C++. The broker scans pending cleanup in bounded pages so an old worker cannot starve later records. Optional gesture receipts hide native bytes and captured target state. Shared semantic receipts project the explicitly allowed direct command feedback; they never expose private intent buffers or unrelated game-state attributes. The native renderer blocks automatic callback-generated world mutations and displays feedback; remaining helper steps require fresh gestures. Full native helper parity is not claimed. See [visual action implementation review](visual-actions-design.md).

`accepted -> queued -> completed/rejected` describes execution; `uncertain` is a reconciliation hold. Save durability is separate: uncheckpointed completion can be rolled back after an engine failure. Recovery fences admission, reconciles backend accepted keys against the actual loaded save/engine receipts, records corrections and only then reopens writes. `resolved_rolled_back` is an explicit operator resolution, never fabricated successful execution. A backend-only reconnect to the same healthy engine uses live status rather than importing requests through a recovery-only API.

The engine keeps bounded live dedupe. A save-bound sidecar retains sparse terminal receipts and `retired_through`. Retirement requires a contiguous backend terminal acknowledgment and engine save inclusion; a missing local-only rejected sequence has no engine effect, while pending outbox work must never be acknowledged through. The engine refuses all retired sequences. The backend records only positively verified per-key checkpoint receipts, never treats sequence order as a save watermark. Receipt discovery can add to an already observed immutable checkpoint generation when an engine result arrives late. The current engine checksum is local corruption detection, not a cryptographic SHA-256 guarantee.

The implemented checkpoint policy schedules saves by elapsed time or before the engine's unretired receipt window fills. It quiesces new dispatch, waits for already queued mutations to drain, requests a checkpoint, and observes its completed manifest before treating receipts as save-bound. The current native generation must be observed and applied to SQLite before another checkpoint can be requested. Busy, transport and save failures retry with bounded backoff; sustained failure blocks new admission. A checkpoint-create reply by itself never marks an action durable.

Native sidecar format 3 records a nonrecursive `parent_checkpoint` anchor with the previous generation's ID, saved tick and checksum. If a crash publishes a native save before SQLite observes it, recovery may adopt that direct successor only after native load verification, an exact parent match to the database, counter checks and per-request receipt reconciliation. The immutable `checkpoint_retired_through` is stored separately from the live `retired_through`; the database's previously observed live prefix is not compared for equality with the parent's saved prefix. Format 2 remains readable, but an unrecorded legacy generation without a parent anchor stays fenced. The native publisher and private state directory are trusted; these checks detect accidental corruption and do not authenticate hostile edits. Recovery records the manifest, receipts and current engine identity durably before asking native code to finish recovery. Dispatch waits for that finish to succeed, and interrupted recovery can rebind a new engine only after the checkpoint proof is verified again.

Checkpoint storage has no automatic pruning policy. Native save files and their session snapshots remain on disk after newer generations publish; the single `ledger.json` pointer is replaced. SQLite retains action rows, checkpoint manifests and their receipt rows. Only projected events have bounded retention. Operators must account for ongoing disk growth; the bounded native deduplication window is not a bound on saved generations or database size.

No exactly-once or bounded-recovery-window release claim is established until live joint fault tests pass. A restored backend database behind retired engine receipts fails closed.

## Native and API chat

The backend is the sole routing/moderation authority. Integration-enabled C++ intercepts native ingress before normal fanout. `chat.pending` is the only ingress-body feed; a trusted roster attests native public keys and current company bindings. Backend maps these to stable credentialless human principals; spectators get world chat only, with private and company chat forbidden. Agents remain operator-provisioned. Participant discovery for text and visual runs performs a fresh authority roster read and refreshes every configured renderer to classify native worker keys before exposing ephemeral human access handles. Retained managed-worker provenance suppresses known private renderers independently of current worker health. If classification or authority checks fail, the list preserves stable participants but omits fresh native handles; an unknown worker can remain visible in a degraded listing. The older snapshot-only, no-renderer-RPC discovery design is superseded. This presentation filter does not change native chat recipients or delivery.

API and native admission share authorization, rate/block checks and one message transaction. It persists stable message/thread IDs, sender label/kind, UTC time, engine tick or an explicit provisional tick, exact identity+company recipients, recipient events and bounded native delivery state. Native client-direct intent becomes an identity-private conversation, never a company-wide expansion. API/public/company/company-direct threads remain durable for agent-only companies without native sockets. Current membership and message-time recipient snapshots govern history; a later grant does not expose earlier private messages.

After durable admission the broker acknowledges native ingress. Native publication carries only a stable delivery ID, message ID, body, sender presentation and approved native public keys. The engine intersects current authorization and deduplicates through the same request sequence ledger; it cannot default to broadcast. Engine failure or unknown delivery becomes uncertain. Backend outage leaves a bounded native queue or generic requester-only unavailable feedback; gameplay continues. Personal block and mute do not grant command authority, and message text is never executed.

## Events and transport

Persisted events use recipient/run-specific opaque cursors and bounded retention. Public cursors never expose global private traffic gaps. SSE wakes on append, has bounded slots/lifetime/socket write times and reconnects through authorized history. Private engine events have a separate bounded cursor/quarantine; native chat bodies do not travel on that channel. Unknown or malformed private events cannot become visual observations.

The included stdlib HTTP server is a local development adapter, with 96 handler slots and 64 SSE slots. The implemented Starlette/Uvicorn ASGI adapter is the default transport on loopback and is intended to sit behind a TLS reverse proxy; it bounds concurrent SSE, PNG and other API work separately. It admits 64 retained image GET responses while limiting image lookup to eight worker threads. Capture POSTs now have eight separate admission slots and worker threads, retained until synchronous generation exits and through bounded response delivery; selected observations additionally share four gateway coordination slots. Image delivery has a five-second deadline. API admission and its worker-thread limit are 64, SSE admission is 64 and Uvicorn's aggregate connection limit is 128. These class maxima are not simultaneous reservations beyond the global limit, and configured admission bounds establish no latency or throughput result. The larger image response bound requires measured RSS; 64 distinct maximum-sized 16 MiB responses could retain roughly 1 GiB before other memory. A local Caddy 2.11.7 binary and checksum were verified, then HTTPS viewer assets, authenticated `/v1/me`, PNG capture, SSE and unauthenticated `401` were smoke-tested with a local CA and curl. There was no external deployment or CA trust installation. Slot configuration is not evidence of the 50-viewer latency/load gate. Static serving is an exact five-path allowlist for the web assets; image bytes use bearer-authenticated fetch and Blob URLs, never credentials in URLs. The reference urllib client rejects credential-forwarding redirects and invokes a caller-owned incoming-event callback without a provider SDK.

## Renderer gateway

A configured mapping binds each run to an existing private renderer socket and owner-only artifact directory. Sockets and directories cannot be shared across runs. One lock covers renderer handshake, immutable company/run binding, capture, file validation, cache commit, controls and visual intent RPCs. Worker restart and every successful control invalidate the controllable interaction image. Its backend age limit is 40 seconds; native frame, lifecycle, window-layout and lease checks can reject input or inspection sooner. The earlier 15-second inspection limit is superseded. The configurable legacy capture interval is 1–60 seconds (default 1): at most one new interaction capture occurs per interval. A repeated request within that interval can return the same valid image without extending its original expiry or gesture age; a control can therefore defer the next capture. Native parking is bounded by the configured park duration and authority lag allowance (eight seconds by default), so a new native capture does not necessarily mean a fresh simulation frame. Capture/control budgets and global cache byte/count/TTL caps bound resource use.

Interaction captures write immutable `frame-<opaque>.png` artifacts; selected observations use a separate `observation-<opaque>.png` namespace. The gateway opens only the exact operation-specific name through a pinned private directory descriptor with no symlink following, validates owner/type/size, PNG signature/CRC/dimensions and IHDR/IDAT/IEND-only RGB8 pixels, then caches bounded bytes. Paths, engine ticks and private revisions never leave the gateway. Each image GET authenticates through the service and returns only the requesting run's original unexpired cached bytes, checking the last detected worker instance without taking its lock or making native RPCs. Detection of a worker replacement atomically clears that run's image cache. A cached PNG is neither a live worker-health check nor proof the image remains a valid gesture target; capture, controls and gestures still perform live checks. Foreign or expired image IDs are unavailable. Read-only image/controls work for both text and visual runs; no synthetic replacement image is produced if rendering fails.

Selected map and native-panel observations are separate from these interaction snapshots. Their POST routes return PNG directly with finite workflow headers, use bounded generation-scoped exact read retries, and acquire no input/inspection proof or thinking-time park. `after_request_id` checks the action ledger's private execution frame and authority boot before drawing the requested presentation; waiting occurs outside the native game thread. Map framing is request-local; the allowlisted native panels obey existing interaction ownership. The [current capture guide](../docs/capture-controls.md) is authoritative for supported selections, labels, panels, retry/cache bounds and MCP image tools.

## Verification boundary

`python3 -m unittest discover -s backend/tests -v` covers durable auth/sequence/recovery, native/API privacy, actual AF_UNIX framing fixtures, canonical schema/projection, HTTP/SSE/binary/static behavior, renderer artifact isolation and visual capture/retry rules. The pinned backend and ASGI checks passed 277 tests without skips; engine wire fixtures alone are not a live OpenTTD world. Public HTTP integration separately verified construction, vehicle setup, delivery income and later modification in all four transport modes. Live smoke verified native chat in both directions, a genuine screenshot and a text loan. A separate verified visual request (`visual-62c8ecaf82f1`, sequence 2) persisted exactly one native command, succeeded, changed the loan principal in an ordinary finances screenshot from 100,000 to 110,000, completed UI acknowledgement and was checkpointed. After the engine, backend and two renderers restarted, the same credential and request ID/payload returned the completed saved receipt; a new genuine screenshot still showed a 110,000 loan without repeated borrowing. The earlier corrupt prototype remained stopped and fenced; no recovery exception was migrated from it. This proves one visual loan restart/retry path. Broader mixed-world fault windows, four-world fault isolation and the provisional 50-viewer/30-minute workload still require measured integration results before release.

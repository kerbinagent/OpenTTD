# Screenshot-bound action broker: implementation and review

Status: the bounded one-command/empty-bundle backend and C++ path is implemented. This document records its reviewed authority boundary and remaining acceptance limits; full native helper parity, broader mixed-world recovery and measured workload acceptance remain separate from the verified public HTTP transport-mode checks.

Public request keeps the existing envelope: `{request_id, action:{name:"ui.apply", parameters:{image_id,gesture:"click"|"drag"|"move",x,y,end_x?,end_y?,button?}}}`. The authenticated immutable visual run supplies company, mode and world; callers cannot supply object IDs, map coordinates, native commands, worker paths or intent bundles. Coordinates are bounded pixels in that run's latest image. Move accepts exactly `image_id,gesture,x,y` and updates ordinary native hover/tooltips; click and drag carry the normal button/endpoint rules. A click may select a normal GUI tool/window, and a later screenshot-bound gesture applies it. The engine continues to enforce normal costs, ownership and ordering.

The worker is a company-scoped trusted replica, parked at the authoritative source frame before ordinary native UI input is processed. Its command-post hook captures the native intent instead of executing/sending it independently. Read-only controls and screenshot capture remain separate; no planner, hidden lookup, semantic map or OCR endpoint is added.

## Minimal state extension

Use the existing action row and shared per-world request sequence. It stores `intent_state` (none/capturing/persisted/aborted/uncertain), immutable private `visual_intent` JSON and digest, `expected_worker_instance_id` before capture, and a monotonic `ui_state` (pending/released/acked). The bundle itself carries the authority and source-frame references. No second workflow queue or request-ID allocator exists.

1. Authenticate, validate the public pixel gesture and admit the immutable public action row transactionally. Public acknowledgment is `accepted`; it never means clicked or executed.
2. Broker locks the configured run's renderer. Validate image ownership/latest revision/TTL and renderer/authority generation. Persist `intent_state=capturing` and the expected worker instance **before** sending `ui.capture`. One request ID causes at most one UI gesture. A same-ID API retry only reads the ledger.
3. Worker `ui.capture` processes the normal UI gesture exactly once while intercepting resulting command posts, and returns a bounded private bundle. Empty bundle means UI-only; initial implementation allows at most one native command. Renderer generation, source authority instance/frame, sender key/client identity and captured native data stay private.
4. Persist the full immutable bundle before any authority dispatch. Compare the public request/run/worker/authority binding. Do not mutate the original public action payload or replace the image ID with a hidden target. If capture fails or the backend crashes while state is `capturing` with no bundle, atomically reject it as `visual_capture_aborted`. No authority dispatch can have happened; the cleanup broker queries/releases/acks only the recorded worker generation. A new screenshot/gesture needs a new explicit request.
5. Dispatch normal `action.submit` with the same request sequence and unchanged public `ui.apply` action, plus top-level private `visual_intent`. Engine canonical dedupe includes that bundle. Authority validates source frame/lease/ownership, then submits captured commands through normal network ordering. It cannot recalculate unseen targets for the public caller.
6. If the bundle was persisted but authority dispatch is uncertain, poll the existing engine sequence/status with the original public action and exact bundle. Reuse that bundle for an idempotent retry only when the engine protocol proves no effect and lease validity; never recapture/reclick or auto-create a fresh request ID. An authority-queued action with unresolved effect remains uncertain. Engine restart/recovery follows the same save-bound request protocol as text actions.
7. On authoritative terminal result, durably persist the internal receipt, then call the existing worker `ui.release(phase="commit")` to unpark it. The normal owner-only native network command packet supplies the existing callback; the backend does not fabricate or forward callback payloads. A terminal authoritative no-dispatch rejection uses `ui.release(phase="reject",authority_rejected=true)`. Engine execution/its ledger result does not depend on replica UI replay; the worker may also resume on its bounded lease TTL and process the owned callback before commit, which is idempotent. Reconcile worker release through `ui.status`; once `ui_state=released` is durable, retry acknowledgement directly without recommitting. C++ treats an unknown acknowledgement idempotently. Acknowledge a cached bundle only after a durable authority terminal result and worker phase completed/rejected. Cleanup scans bounded pages so an old worker does not starve later requests. Public JSON/events expose only request ID/status; normal rendered UI carries gameplay feedback. Capture/control serialization prevents another gesture overtaking this lifecycle.

The first slice is one command or an empty bundle. The native renderer blocks automatic callback-generated world mutations and shows feedback; the agent performs remaining helper steps with fresh screenshot-bound gestures. This does not forward callback children through another broker workflow, and full native helper parity is not claimed. No multi-command atomicity claim is made. Source-frame leases and worker parking are C++ owner responsibilities; backend checks exact binding and stores their result without inventing visibility guarantees.

## Crash and retry boundaries

- Before durable admission: no accepted action, retry is a normal first request.
- Accepted before capture marker: broker may validate and capture once.
- Capturing with no persisted bundle: proven unsent to authority; atomically reject as `visual_capture_aborted`, then clean up only the recorded worker generation; never reclick.
- Persisted bundle before authority send: preserve bundle and source lease; no fresh capture.
- Authority queued, no durable result: poll existing sequence and exact bundle; a truly ambiguous effect remains uncertain.
- Result persisted, worker not released: retry idempotent `ui.release` and inspect `ui.status`; native network replay supplies callback, never rerun gesture or world command.
- Release state persisted, acknowledgement missing: skip commit and status replay; acknowledge directly, including idempotent unknown ack after a lost reply.
- Worker replacement: old image and capture generation invalid; no hidden rebinding of a request to a new replica.
- Loaded save rolls back an uncheckpointed result: explicit correction/uncertain state, then operator resolution under the normal recovery fence; no automatic replay.

## Alternatives and complexity

Raw tile/object action parameters for visual credentials violate observation isolation; rejected. Re-running the click on every retry duplicates world actions or clicks a different later UI; rejected. Encoding a bundle in the public action result leaks native IDs/coordinates; rejected. A separate visual workflow service or durable queue duplicates the existing action ledger; rejected. The existing row's capture marker, worker fence, immutable bundle and UI cleanup state preserve the engine/backend authority split.

The C++ implementation defines `ui.capture`, `ui.status`, `ui.release`, bundle size/keys, source-frame lease, owner binding and native dedupe identity. Backend conformance checks those shapes before persistence. Public click/drag/move pixels and left/right click are explicitly validated; drag is left-button only, and move has no button or endpoint. There is no arbitrary keyboard/script input. The configurable capture interval is 1–60 seconds (default 1) and limits new native captures, not fresh simulation frames: native parking can preserve one frame for roughly eight seconds. Reusing a valid image during the interval does not extend image expiry or gesture age; a control may have to wait before another native capture.

Independent review approved the bounded implementation on the condition that authority terminal state is durable before worker commit, and that dispatch/recovery gate all visual rows on a persisted bundle. Current C++ already has `ui.status` and idempotent `ui.release(commit/reject/ack)`; authority completion is independent of replica UI completion. Captures aborted before bundle persistence are local terminal rejections, while ambiguous authority-queued outcomes retain the recovery hold. Live smoke has verified genuine screenshot capture; full four-mode interaction, native helper parity, restart fault windows and load remain separate acceptance work.
